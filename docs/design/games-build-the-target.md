# משחק "בנה את היעד" (Build the Target) — איפיון מלא

> משחק חינוכי ראשון בדף המשחקים של התלמיד. עלות שחקיה: **200 כוכבים**.
> מטרה: לפתח חשיבה מספרית גמישה (פירוק, סדר פעולות, אסטרטגיה) — לא דריל רגיל.

---

## 1. הרעיון בקצרה
המערכת נותנת **מספר יעד** + כמה **אריחי מספרים**, והתלמיד מרכיב **ביטוי חשבוני** שמגיע ליעד.

```
        ┌─────────── יעד: 24 ───────────┐
        │                               │
   אריחים זמינים:   [3] [8] [2] [1]   אופרטורים: [+] [−] [×] [÷] [( )]
        │                               │
   התלמיד בונה:   ( 3 × 8 ) × ( 2 − 1 )  =  24   ✓ נכון!
```

יש כמה דרכים נכונות → התלמיד **חוקר ומתנסה**, לא משחזר תשובה אחת.

## 4. מחולל היעדים (Rule‑Based) — מובטח שיש פתרון

הטריק: **מייצרים אחורה** — קודם בונים פתרון, וממנו גוזרים את היעד. כך תמיד קיים פתרון.

```
┌─ generateTargetPuzzle(difficulty) ───────────────────────────┐
│ 1. params לפי קושי:                                          │
│      N tiles, range מספרים, אופרטורים מותרים, useAll?        │
│ 2. בחר N מספרים אקראיים מהטווח           → nums = [3,8,2,1]  │
│ 3. שלב אותם באופרטורים אקראיים חוקיים     → (3×8)×(2−1)       │
│ 4. חשב את התוצאה                          → target = 24      │
│ 5. guardrails:                                               │
│      • target שלם וחיובי ובטווח?                             │
│      • target ≠ אחד המספרים (לא טריוויאלי)?                  │
│      • חילוק → תוצאה שלמה (אלא אם רמת שברים)?                 │
│      • אין ביניים שלילי (ברמות צעירות)?                      │
│    ❌ נכשל → חזור לשלב 2 (retry, מקס' ~30)                    │
│ 6. החזר { target, tiles: nums, sampleSolution }             │
└─────────────────────────────────────────────────────────────┘
```

- `sampleSolution` נשמר רק כדי להציג ב‑"💡 רמז" / "הצג פתרון" — **לא נחשף מראש**.
- אותו עיקרון של המחולל הקיים: כללים + פרמטרים, בלי מאגר קשיח. **אדפטיבי** (הקושי מרמת התלמיד).

### מדרגות קושי (ברירת מחדל מוצעת)
| רמה | גילאים | N | טווח | אופרטורים | useAll | יעד |
|-----|--------|---|------|-----------|--------|-----|
| קל | גן–ב' | 3 | 1–10 | + − | לא | ≤ 20 |
| בינוני | ג'–ו' | 4 | 1–12 | + − × | לא | ≤ 100 |
| קשה | ז'+ | 4 | 1–20 | + − × ÷ ( ) | כן | ≤ 200 |
| מתקדם | תיכון+ | 4 | שברים/שליליים | הכל + ^ | כן | משתנה |

## 5. בדיקת תשובה (צד לקוח, בלי `eval`)

התלמיד בונה ביטוי ע"י **שיבוץ אריחים בסלוטים** (builder מובנה) → אין טקסט חופשי → אין `eval`.

```
┌─ checkAnswer(expressionTokens, puzzle) ──────────────────────┐
│ 1. תקין תחבירית? (מספר/אופרטור לסירוגין, סוגריים מאוזנים)    │
│ 2. אריחים חוקיים? (כל מספר ≤ פעם אחת; אם useAll → כולם)      │
│ 3. evaluate בטוח (shunting‑yard / מחשבון פנימי קטן)          │
│ 4. result === puzzle.target ?  → ✓ נכון  :  ✗ נסה שוב        │
└─────────────────────────────────────────────────────────────┘
```

## 6. מנגנון 200 הכוכבים (צד שרת — מאובטח, כמו חנות האווטארים)

```
 לקוח                          שרת (GameService)                DB
   │   POST /games/play           │                              │
   │ ───────────────────────────► │                              │
   │                              │  user.totalStars ≥ 200 ?     │
   │                              │ ──────────────────────────►  │
   │                              │ ◄──────────────────────────  │
   │            ┌─────────────────┴─────────────────┐            │
   │     אין מספיק│                                  │ יש מספיק   │
   │            ▼                                    ▼            │
   │  402 INSUFFICIENT_STARS              totalStars -= 200      │
   │  { needed:200, have:X }              save(user)             │
   │ ◄──────────────────────              { gameId, seed,        │
   │                                        newBalance }         │
   │ ◄────────────────────────────────────────────────          │
   │                                                             │
   │  אם 402 → 🔔 התראה "ענה על עוד שאלות"                       │
   │  אם 200 → פתח משחק (seed → מייצר 5 חידות)                   │
```

- **ניכוי הכוכבים תמיד בשרת** (לא ניתן לרמות מהלקוח) — אותו דפוס מוכח מ‑`selectAvatar`.
- ה‑`seed` מאפשר ייצור חידות דטרמיניסטי בלקוח (MVP). הקשחה עתידית: ייצור החידות בשרת.

## 9. יושרות קצה
- אין מספיק כוכבים → התראה + קישור לתרגול (להרוויח כוכבים). **לא** מורידים כוכבים.
- יציאה באמצע משחק → הכוכבים כבר נוכו (כמו כרטיס כניסה). *(להחליט: החזר אם יצא לפני סבב 1?)*
- רענון דף באמצע → לשחזר את ה‑seed/סבב מ‑localStorage כדי לא לאבד שחקיה ששולמה.
- חידה בלי פתרון → לא יקרה (ייצור אחורה מבטיח פתרון).
- RTL/LTR → ביטויים LTR, ממשק עברי RTL.

## 10. שאלות פתוחות להחלטה (לפני מימוש)
1. **תגמול בסיום?** משחק הוא "בידור" net‑negative (משלם 200, לא מקבל בחזרה) — או מעט כוכבים/באדג' על סיום מושלם? *(המלצה: net‑negative + באדג' "בנאי היעדים", כדי שכוכבים יישארו משמעותיים.)*
2. **טווח גילאים ראשון** למיקוד הקושי? *(משפיע על ברירות המחדל בטבלה.)*
3. **טיימר?** *(המלצה: בלי לחץ זמן — זה משחק חשיבה; אולי בונוס‑זמן רך בלבד.)*
4. **כמה חידות לשחקיה?** *(המלצה: 5.)*
5. **חובה להשתמש בכל האריחים?** *(המלצה: תלוי‑קושי — קל=לא, קשה=כן.)*
6. **ייצור חידות:** לקוח (seed) או שרת? *(המלצה ל‑MVP: לקוח עם seed; ניכוי כוכבים בשרת.)*
